# Mordheim campaign site

Astro 7 on Vercel. Every page reads the database, so they are all serverless functions: the home page and the scenario pages cached at the edge for a few minutes, the personal ones never. Postgres (Neon) via Drizzle; email-and-password sign-in via Better Auth (no emails are sent; an optional `CURFEW_INVITE_CODE` gates sign-up).

## Start here

`AGENTS.md` is the one-minute version of this file for any tool. `docs/agents/` goes deeper: `workflow.md` (local stack, definition of done, tests, commits), `architecture.md` (how the record, the nights and the layers fit), `glossary.md` (the campaign's words mapped to code), `writing.md` (the four voices). The common tasks are skills under `.claude/skills/`: `record-battle`, `add-warband`, `town-cryer` (now about the site's own forms and the voice, since the record lives in the database), `curfew-pack`, `curfew-engine`, `schema-change`, `preflight`. Use the matching one before improvising.

## Commands

- `npm run dev` — local dev with a PGlite database under `.pglite/`, a name-only dev sign-in, and the Debug strip (step nights with `?date=`; game masters only, on in production too; with the strip on, a game master's requests are dry runs that save nothing, see `src/server/curfew/dry.ts`; the Watch House never takes a steered clock). No `.env` needed.
- `npm test` — engine, ledger, Town Cryer and service tests (`node --test`, TypeScript run natively; relative imports need `.ts` extensions).
- `npm run check` — `astro check`. Keep it at 0 errors.
- `npm run build` — Vercel build; on a production deploy it first applies any pending migration (`scripts/migrate.mjs`). `npm run db:generate -- --name <name>` after a schema change and commit the files under `drizzle/`; `npm run db:reset` wipes the local database.
- Done means all three pass (CI runs exactly them), plus `node .claude/skills/record-battle/scripts/check-history.mjs` after touching the seed archives or rosters and `node .claude/skills/curfew-pack/scripts/lint-pack.mjs` after touching a built-in pack. The `preflight` skill runs the lot.

## Content model: the campaign's record is in the database, the rules and the seed are source

The campaign's record is managed on the site and kept in Postgres: warbands and their members (owned by a player, tended by the owner or a game master at `/warbands/<id>/`), scenarios upcoming and played with every warband's own telling (`/scenarios/`), the Town Cryer's articles, and the Curfew's content documents (the Omens, Moons, charms and one pack per place, edited as JSON in the Watch House at `/admin/content/`). The database also holds what the Curfew nights generate: ledgers, dispatches, players, sessions, midnight runs, and the log of where the campaign is (`curfew_moves`). There is no page without a database any more; `npm run dev` has PGlite.

- **Seed once, then the database rules.** The files under `src/data/` (`warbands.ts`, `news.ts`, `chronicle.ts`, `history/*.json`, `curfew/*.json`, `curfew/locations/*.json`) are fixtures: imported once when the tables are empty (`src/server/campaign/seed.ts`, `src/server/content/curfew.ts`) and the engine's built-in defaults for the tests and the linter. Editing them changes nothing on a database that has been seeded; the change is made on the site. A rule of the game, the campaign's constants (`campaign.json`: id, start, timezone, anchor, tuning) and the code stay source.
- **Roles.** A player keeps one warband and edits only it. A game master (`user.role = 'gm'`, granted by an admin in the Watch House) runs the campaign: scenarios, every warband, the Cryer's articles and notices, the content documents, moving the campaign. An admin (`ADMIN_EMAILS`) is a game master who also keeps the accounts: roles, reset words, sign-outs, burning and releasing ledgers, midnight by hand. `src/server/roles.ts`.
- **One owner per warband, and the ledger follows.** `warbands.owner_id` says who keeps a warband; claiming a ledger at `/curfew/` claims the warband, giving one up frees both, and a game master handing a warband to another player moves the ledger with it.
- Locations keep their split: a place is a content document (`location:<id>`, the same shape as the JSON under `src/data/curfew/locations/`), *which* place the campaign is in is a game master's switch logged by night. The Crossroads too: roads and effects are pack content; which crossroads a night met is the ledger's.
- When adding a feature, ask who writes the thing: the nights (ledger state, dispatches), a player (their warband, their part of a scenario), a game master (a scenario, an article, a pack), or the code (a rule). Only the last is a commit.

## Where things are

- `src/curfew/engine.ts` pure Night engine (seeded, deterministic; `Location`, `locationForNight`, `errandAt`, `tokensFor` say what a place offers; `takeRoad` resolves a road at a crossroads). Its content (`OMENS`, `MOONS`, `TOKENS`, `CURSES`, `TOKEN_TYPES`, `LOCATIONS`) are live bindings: `useContent(docs)` puts the database's documents in force, `BUILT_IN_DOCUMENTS` are the files. `packs.ts` validates a document and slims it for the browser; `roster.ts` is pure helpers over a loaded `Roster`. `ledger.ts` pure ledger ops on `WarbandState` (`decide` takes a road; `reconcile` defaults a waiting crossroads before the next night). `cryer.ts` turns a night into Town Cryer dispatches, worded where the night happened, and waits for a crossroads to be decided. All three have tests beside them.
- `src/server/` is server-only: `env.ts` config, `db/` schema and client, `auth.ts` Better Auth, `roles.ts` who may do what, `api.ts` the frame every JSON route shares, `curfew/service.ts` load-reconcile-change-save with optimistic locking and the nightly `reconcileAll` (every entry point first primes the content and loads the roster from the database), `campaign/` the record (`seed.ts`, `roster.ts` warbands and members, `scenarios.ts`, `news.ts`), `content/curfew.ts` the Curfew's documents.
- `src/campaign/model.ts` is the record's shape (`Warband`, `Member`, `Scenario`, `ScenarioWarband`, `ScenarioMember`, `OutOfAction`, `NewsArticle`); `rulebook.ts` the rulebook's scenario names.
- `src/pages/api/warbands/[action].ts` and `src/pages/api/scenarios/[action].ts` are the players' and game masters' JSON API (zod-validated, answer with the warband or scenario as it now stands); `/warbands/`, `/warbands/[id]/`, `/scenarios/`, `/scenarios/[id]/` are the pages, mobile first, wired by `src/lib/manage.ts` (`data-act` buttons, `data-api` forms) with `src/styles/manage.css`.
- `src/pages/api/curfew/[action].ts` JSON API (same-origin, zod-validated, always answers with the whole ledger view). `src/pages/api/cron/midnight.ts` nightly cron.
- `src/server/account/service.ts` reset words: issued only by the game master in the Watch House (hashed with Better Auth's scrypt, two-day expiry), traded for a new password at `POST /api/account/reset`, spent on use. Not self-service by design. There is no email anywhere in the system.
- `/admin/` is the Watch House, the game masters' console: `src/pages/admin/index.astro`, `src/server/admin/service.ts` (overview, players, burn/release, notices, midnight by hand, moving the campaign), `src/pages/api/admin/[action].ts` (each action names the least role that may call it). `/admin/content/` edits the Curfew's documents. `/admin/odds/` (`src/pages/admin/odds.astro`, `src/curfew/odds.ts`) lays out the odds by tilt and simulates nights, read from the engine's constants (`outcomeOdds`, `TOKEN_CHANCE`, `FAVOUR`, `YIELDS`, `PRINT_CHANCE`, `crossroadsChance`); change a dial there, not on the page. Admission for game masters and admins (`admission` in `src/server/admin/guard.ts`); admins by `ADMIN_EMAILS` (`isAdminEmail` in `env.ts`); under the dev sign-in everyone is an admin. Styles in `src/styles/admin.css` on top of Curfew's tokens.
- `src/lib/calendar.ts` is the Imperial Calendar (pure, tested): `imperialForDate` turns a real day into an Imperial one counted from the campaign anchor in `campaign.json` (the first game, `playedOn` in its record), `formatImperial`/`parseImperial` read and write "Marktag, 5th of Pflugzeit, 2007 IC". Every date shown to players goes through it; a scenario record carries both its written Imperial `date` and the real `playedOn`.
- Seed and built-in content: `src/data/warbands.ts`, `news.ts`, `chronicle.ts`, `history/*.json`, `curfew/*.json`, `curfew/locations/*.json`. A place's band and mark (`public/curfew/places/`, cut by `scripts/curfew/render-places.py`, framed by `art.focus` in the pack) are still files in the repository: `src/components/PlaceBand.astro` is the letterhead both Curfew pages carry, so a new place pasted in the Watch House needs its images committed. Prose follows `src/data/curfew/STYLE.md`; the plan and status live in `src/data/curfew/PLAN.md`.

## Conventions

- Keep resolution a pure function of (campaign, night, warband, orders, location); the server and tests rely on it. The location of a night comes from the move log, never from "now".
- The ledger refuses with `LedgerError`; its message is shown to the player as written.
- Never put secrets or `import.meta.env` reads in client scripts; go through `src/server/env.ts`.
- Ids are forever: warband and member ids (chosen once, by the roster service from the name) key the scenario records, the ledgers and the dispatches; Omen, charm and place ids sit in ledgers; `campaign.json`'s `id`, `start`, `timezone` and `anchor` seed every draw and date. Do not rename them once play has begun.
- Every service that changes the record takes the `Actor` and refuses with `LedgerError(message, status)` when the role does not allow it; the routes only validate and dispatch (`src/server/api.ts`). Battles and victories are counted from the played scenarios, never stored.
- Tests are `node:test` with `.ts` extensions on relative imports in `src/curfew` and `src/server`; a rule change ships with its test. Service tests run on an in-memory PGlite and are ordered within a file.
- Prose is content: British spelling, typographic apostrophes, no exclamation marks, the voice of its surface (`docs/agents/writing.md`). Commit messages are sentence-case imperative with a body that says why.
- Work on the branch you were given; do not open a pull request unless asked; never commit `.env`, `.pglite/`, `dist/` or hand-written SQL under `drizzle/`.
